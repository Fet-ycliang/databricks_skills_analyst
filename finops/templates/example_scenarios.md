## 場景 1：成本概覽與深入分析

### 初始問題
**用戶**：「上個月的 Azure 成本總額是多少？」

**Space**：`Azure CostUsage Analytics`

**預期輸出**：
```
分析：上個月的 Azure 總成本為 $19,600。主要成本驅動因素為：
- Virtual Machines: $5,000 (25.5%)
- Storage: $3,000 (15.3%)
- Databases: $2,500 (12.8%)
- 其他服務: $9,100 (46.4%)

與上個月相比，成本增加了 3.2%。

建議的後續問題：
- 能否按資源群組細分？
- 顯示過去 3 個月的成本趨勢
- 哪些服務成本增長最快？
```

### 追問 1
**用戶**：「能否按資源群組進行分類？」

**操作**：使用相同的 `conversation_id` 呼叫 `ask_followup()`

**預期輸出**：
```
分析：以下是按資源群組的成本細分：

生產環境: $11,200 (57.1%)
開發環境: $5,600 (28.6%)
測試環境: $2,800 (14.3%)

生產環境驅動了大部分成本。考慮優化開發和測試環境的資源分配。
```

## 場景 2：儲存容量分析

### 問題
**用戶**：「我們使用了多少儲存？成本如何？」

**Space**：`Azure Storage Analytics`

**預期輸出**：
```
分析：您目前的 Azure 存儲使用情況為：

總存儲容量: 5.2 TB
- Blob 存儲: 4.0 TB (76.9%)
  - 熱訪問層: 2.8 TB ($112/月)
  - 冷訪問層: 1.2 TB ($24/月)
- 檔案共享: 0.8 TB (15.4%) - $32/月
- 佇列和表: 0.4 TB (7.7%) - $16/月

每月存儲成本: $184

建議：
1. 您有 1.2 TB 冷存儲，可考慮歸檔層進一步節省成本
2. 實施生命周期策略自動歸檔舊數據

建議的後續問題：
- 哪些 Blob 容器最大？
- 存儲成本趨勢如何？
- 可以節省多少成本？
```

## 場景 3：工作流監控

### 問題
**用戶**：「我們目前執行中的工作流有多少個？它們的成功率如何？」

**Space**：`Azure Workflow Analytics`

**預期輸出**：
```
工作流執行狀態概覽

執行中的工作流：12 個

按狀態分類：
- ✅ 成功完成：254 個 (92.4%)
- 🔄 執行中：12 個 (4.4%)
- ⚠️ 警告：5 個 (1.8%)
- ❌ 失敗：4 個 (1.4%)

總體成功率：92.4%
- 上個月：89.2%（↑ 3.2% 進展）
- 最近 7 天：95.1%（高於平均值）

頻繁失敗的工作流（需注意）：
1. DataSync Daily Job - 失敗 2 次（最後：2 小時前）
   - 原因：連接超時
   - 建議：檢查資料庫連線配置

建議的後續問題：
- 為什麼 DataSync Daily Job 經常超時？
- 過去 30 天的工作流成功率趨勢如何？
- 哪些工作流消耗資源最多？
```

## 場景 4：主題切換

### 情境
用戶從成本分析切換到儲存分析

**操作流程**：
1. 刪除當前對話：`delete_conversation(space_id, conversation_id)`
2. 啟動新對話：`start_conversation(question, new_space_id)`
3. 告知用戶正在切換到不同的資料來源

**範例**：
```
用戶：「過去 6 個月的成本趨勢是什麼？」
→ start_conversation() (Azure CostUsage Analytics)

用戶：「現在我想看儲存使用量」
→ delete_conversation() (清理舊對話)
→ start_conversation() (Azure Storage Analytics)
```

---

## 最佳實踐

1. **從廣泛到具體**：先查詢總體情況，再深入細節
2. **使用追問功能**：維持對話上下文以進行多層分析
3. **正確切換主題**：切換 Space 前必須刪除舊對話
4. **呈現建議問題**：向用戶展示 Genie 的建議以引導探索
5. **保存 conversation_id**：所有相關追問都需要使用相同的 ID
